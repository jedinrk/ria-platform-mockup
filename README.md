# Portfolio Console mockup

Static, browser-local RIA workflow prototype. Entry point: `index.html`. Deploy the complete repository root to GitHub Pages; no build step is needed.

- **Portfolios:** searchable Household / Account overview filtered by model, original AUM, threshold-relative Aggregated drift bars, editable portfolio thresholds, a stated review reason (asset class / exposure / both) and a financial-plan column showing whether the household is funded or the year a gap first appears with its liquidity runway, and a concise row expansion showing drift by asset class, contributing accounts and the worst bucket per exposure lens. Drift says whether a portfolio is still shaped as agreed; the plan column says whether the family can afford what they are committed to.
- **Assets & liabilities (tab 1):** household balance sheet — assets by liquidity band with days to cash, liabilities with interest still to pay, net worth and debt to assets, a twelve-month cash-flow projection, and yearly expenses by category with a five-year inflated view. Income, liabilities and needs are household facts, so an account shows its household's plan. See [docs/financial-planning.md](docs/financial-planning.md).
- **Allocation & drift (tab 2):** actual versus approved client target, distribution chart, holdings hierarchy with review state and liquidity/physical tags, value gaps and exposure lenses. Households get the same table against combined client targets.
- **Client target (tab 5):** model assignment, asset-class adjustments, per-bucket lens limits, included-assets dialog, draft saving and approval. An approved lens limit replaces the model-implied target and/or the default band and is what Exposure drift and the portfolio list compare against.
- **Models:** searchable library with an allocation preview and last-updated date, a focused editor, Model comparison, which includes an Intended profile view. The model Sector view carries the original's equity concentration check against the firm cap. Revisions belong in the Audit log.
- **Audit log:** one chronological feed of model publications and client target approvals, filtered by portfolio/model, action, actor, status and date range. Each entry opens to before/after values. Each account's own target revisions sit on its Client target tab.
- **Gap summary & trades (tab 3):** gap summary, then a rebalance scenario with suggested trades, liquidity and short-term-gain constraints, an estimated tax figure after loss offsets and the long-term exemption, and a projected before/after allocation. A rebalance is cash-neutral and never sells from a class that is already below target. Approval records a decision; it does not place a trade.
- **Cash & planning (tab 4):** raise or invest, gross proceeds versus net cash after estimated tax, lump-sum or staged deployment, selection strategy, loss harvesting, and a per-portfolio event history. Scenarios never change recorded holdings or the approved target. The same tab carries the household plan: income and assumptions, planning flags, a 30-year projection, a contingency cash raise ordered cheapest-first, a recurring investment plan, and editable liability and recurring-need registers.
- **Bulk planning** remains out of scope: the engine is single-portfolio for now.
- **Security master:** firm-wide instrument configuration, built to the `RIA-AssetConfig-Type1` sheet. One row per instrument; identity, symbol, rating, price and asset type arrive fixed from the source, while asset class, **super sector**, sector and sub-sector are the firm's editable classification and nest within each other. Edits are staged and applied after a review stating the value and portfolio count affected. Super sector, sector and sub-sector feed every exposure view; asset class also gates the credit and duration view. Opening a row shows that instrument type's own attributes, grouped by whether a feed, the firm or the client owns them; filtering to one type turns them into comparable columns. See [docs/security-master.md](docs/security-master.md). Reclassifying changes analysis going forward and does not restate an approved snapshot.

## Data and persistence

`data/original-mockup.json` contains six original households, twelve accounts, 228 account holdings, model weights, classifications, illustrative cost/tax inputs and cash-planning defaults. Its instrument master is the 31 instruments of `data/security-master.json`; the sample portfolios hold nineteen of them. Total sample assets: ₹1,968 lakh (₹19.68 crore), dated 3 October 2026. Every original asset starts included. Account types are inferred from names, not verified ownership records.

`scripts/build-security-master.cjs` builds `data/security-master.json` from the revised wireframe to the sheet's column set, and `scripts/apply-security-master.cjs` applies it to the dataset. `scripts/extract-original.cjs` regenerates JSON from the original HTML without running its DOM application. It accepts the HTML path and a Babel parser module path and emits JSON to stdout. The source hash and unrounded deterministic holding data are retained; the current extraction matches byte-for-byte.

Saved models use `portfolio-model-design-v3` and account targets `portfolio-original-targets-v2`; classification changes use `portfolio-security-master-v2`. Earlier four-client examples under `portfolio-client-targets-v1` are not overwritten and remain readable in History. Initial approvals are illustrative workflow entries, not original real approvals. No backend, live pricing, current tax guidance or trade execution is provided. Storage is specific to the browser/origin. Legacy `clients.js` remains in the repository but is no longer loaded.

Household financial plans use `portfolio-financial-plans-v1`; `data/financial-plans.json` is rebuilt by `scripts/build-financial-plans.cjs`. Review-rule settings use `portfolio-review-rules-v1`. Blank portfolio thresholds inherit the firm default; explicit household and account overrides remain independent. Changing these rules only changes review flags and bar scales—it never changes models, targets or holdings.

## Verification

Run `node --test tests/*.test.cjs`. Serve the root with a local HTTP server; the JSON-backed app does not support direct file URLs.

`bootstrap.js` loads data and scripts in order. Increment the release token in `bootstrap.js` and `index.html` when changing assets to prevent mixed cached releases. Data-load failure shows a retry screen without resetting saved work.

`docs/original-mockup-traceability.md` maps every component of the original wireframe to delivered / refined / deferred / dropped, with reasons. See `ROADMAP.md` and `docs/portfolio-workspace.md` for the current design scope. The complete designer-facing specification and phased refinement plan is in `docs/ui-ux-refinement-plan.md`.
